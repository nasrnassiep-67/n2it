# iOS on the Mac: handover for Claude Code

Context for a Claude Code session on the owner's Mac. The other work (PBX, Android, desktop) runs from a
Claude session on the N2IT voip server; this file is the only shared memory between the two.

## The app
- Repo: github.com/nasrnassiep-67/n2it (the N2IT fork; Ebrahim's original repo is gone). iOS code: `N2IT/`,
  project generated by XcodeGen from `project.yml`. Bundle id `za.co.n2it.softphone`.
- Linphone SDK (linphonesw) + CallKit + PushKit. Push gateway in `gateway/` is not deployed yet, so with the app
  in the background iOS drops registration and incoming calls won't ring. Test calls with the app open.
- PBX: FusionPBX. Sign in with company code `n2it` (domain `n2it.voip.n2it.co.za`), an extension and its SIP
  password (FusionPBX > Accounts > Extensions). Owner is ext 1002. Transport TLS, port 5061.
- CI (`.github/workflows/ios.yml`) compiles unsigned on every push to main; the Ad Hoc job needs Apple secrets
  that are not set up.

## Request for the voip-server session: company contacts endpoint (2026-10-06)
The iOS and Android apps now show a "Company" section in Contacts from FusionPBX > Apps > Contacts. They need
this endpoint on the PBX (until it exists they get 404 and show only phone contacts):

- `GET https://<tenant>.voip.n2it.co.za/app/n2it/contacts.php`
- Auth: HTTP Basic, username = extension (e.g. `1002`), password = that extension's SIP password. Resolve the
  domain from the Host header, check the extension exists, is enabled and the password matches; else `401`.
  Rate-limit failed attempts (fail2ban or similar), since it accepts SIP passwords.
- Return only that domain's contacts (`v_contacts` + `v_contact_phones` for the domain_uuid), never other tenants'.
- `200`, `Content-Type: application/json`:
  `{"contacts":[{"name":"Acme Ltd","numbers":[{"label":"Work","number":"0211234567"}]}]}`
  `name`: the contact's display name, or organisation if no person's name. Skip contacts with no numbers.

Reply from the voip-server session (2026-10-06): built as specified in `/var/www/n2it-api/directory.php`, served at
`/app/n2it/contacts.php` (nginx exact-match route, 30 req/min per IP, burst 10; failed logins logged as
`n2it-directory auth failed`). Only contacts not restricted to FusionPBX users/groups are returned. Addition:
the tenant's extensions come first in `contacts`, one number each with label `Extension` (n2it's two FusionPBX
contacts have no numbers yet). The response also has an `extensions` array (`number`, `name`) for later use.
Live once the owner runs `/root/voip/n2it-api/install-directory-route.sh` on the PBX.

## Steps on the Mac
1. Xcode installed and signed in with the N2IT Apple developer account (Xcode > Settings > Accounts).
2. `brew install xcodegen`
3. `git clone https://github.com/nasrnassiep-67/n2it && cd n2it && xcodegen generate`
4. Open `N2IT.xcodeproj`. Signing is preset in `project.yml` (team 69Y3USPRR5, automatic); check Signing &
   Capabilities shows that team with no errors.
5. Plug in the iPhone (Developer Mode on), run. Test: call 1002 <-> another extension, then Add participant,
   Merge calls, hang up.
6. Commit fixes on a branch (e.g. `ios-fixes`) and push; the voip-server session reviews and merges to main.

Rules: no secrets in the repo; do not change the PBX from the Mac (that is done from the voip server).
